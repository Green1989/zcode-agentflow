每个 Phase 使用一个新的 Agent 会话更稳妥。把对应文件全文复制给执行 Agent；在它报告 Phase Exit 全部满足、提交记录和测试证据后，再复制下一个 Phase Prompt。

`phase-completion-review-prompt.md` 是可选的独立复核 Prompt：建议在 Phase 0、3、6、8 完成后交给另一个 Agent 做只读审核。

## 使用原则

- 不要一次把 9 个 Phase 全部交给同一 Agent 无人值守执行。
- Phase 0 的真实 capability 发现优先级最高；出现 required gate=false 时暂停。
- Phase 3 是持久化与恢复质量门；Phase 6 是状态机质量门；Phase 8 是最终验收门。
- Prompt 中的 Windows 路径沿用当前仓库配置。仓库迁移后，先统一替换路径。
- 所有 Prompt 均要求一 Task 一 Commit、TDD、阶段回归、无 push/merge。

## Phase 0 Prompt 的修订说明

用户原稿整体质量较好，本包版本主要做了这些增强：

- 可自动检测的前置条件由 Agent 自己运行命令检查，不先向用户提出一揽子确认问题；
- 只有 ZCode UI 触发等真正无法自动化的步骤才请求用户配合；
- 若 `docs/capabilities.json` 已存在，不盲目覆盖，先核验证据和来源；
- 每项 capability 记录“命令/观察/脱敏证据/结论”，避免只填布尔值；
- 明确增量提交 `docs/capabilities.json` 的方式；
- 增加分支、工作区、秘密扫描、Phase Exit 和 BLOCKED 报告要求。
